# conversation-skill-loading Specification

## Purpose

让 Dext 普通对话能按任务读取已勾选 Skill 的当前版本，减少续聊请求中重复的正文，同时保留会话级持续应用、命令和脚本显式调用的行为。

## Requirements

### Requirement: 会话选择决定 Skill 加载策略

Dext SHALL 在普通对话的 Skills 菜单中显示「Lazy」和「Always」及勾选状态，并按会话保存用户的显式切换。新会话 SHALL 默认按需加载，并在「Lazy」的悬停提示中说明此默认设置。既有会话缺少策略字段时 SHALL 按每轮应用恢复，并按既有规则恢复勾选状态。

#### Scenario: 新建普通对话

- **WHEN** 用户从采用每轮应用且已有勾选项的会话新建普通对话
- **THEN** 新会话选中「Lazy」，初始未勾选 Skill
- **AND** 勾选项表示该 Skill 可用于此会话

#### Scenario: 旧会话恢复后明确切换

- **WHEN** 用户恢复未保存策略字段的旧会话，并将它切换到「Lazy」后重新打开
- **THEN** 首次恢复选中「Always」且所选全文按原流程进入请求
- **AND** 再次打开选中「Lazy」并保留原勾选项，其他会话的设置不受影响

#### Scenario: 需要持续应用所勾选的 Skill

- **WHEN** 用户勾选需要持续应用的 Skill，并将会话切换到「Always」
- **THEN** 每轮请求都直接加载该会话所勾选的有效 Skill 全文
- **AND** 取消勾选后，该 Skill 不再由 Dext 注入后续请求

### Requirement: 普通按需请求提供当前版本的简短清单

按需模式中的 Ask、Plan 和 Agent SHALL 通过现有文本输入提供可用勾选项的名称、短描述、实际 `SKILL.md` 路径与 revision。与任务相关的 Skill 在上下文缺少对应版本正文时 SHALL 使用授权文件工具读取。清单 MUST NOT 包含正文或未勾选项。项目内路径 SHALL 优先相对于工作区根目录表示。会话历史可能带有旧范围时，空范围 SHALL 随当轮请求明确传递。

#### Scenario: 勾选整包后发送普通请求

- **WHEN** 用户勾选包含多项 Skill 的包并发送无关的普通问题
- **THEN** Dext 只在文本中提供有效勾选项的名称、短描述、实际路径和 revision，完整正文不会随该请求发送
- **AND** 指令要求仅在相关任务需要当前正文时读取

#### Scenario: 未勾选任何 Skill

- **WHEN** 用户在按需会话中取消勾选全部 Skill 后发送普通请求
- **THEN** 该请求没有非空 Skill 清单或由勾选引入的 Skill 正文
- **AND** 历史可能携带旧范围时，请求明确标记当前范围为空，已取消的 Skill 即刻失效

#### Scenario: 实际执行 Agent 选择对应版本

- **WHEN** 勾选的同一 Skill 有 Agent 专用版和共享版，且执行 Agent 发生变化
- **THEN** 清单优先使用实际执行 Agent 的专用版，否则使用共享版，并提供该版本的实际描述、路径和 revision
- **AND** 两种版本均不可用时反馈该 Skill 的版本缺失

### Requirement: 当前版本允许按上下文重新读取

每次按需请求 SHALL 提供当前解析结果。Agent SHALL 仅在当前范围包含该 Skill 且上下文拥有同一路径、同一 revision 的完整正文时复用。已读记录 MUST NOT 成为跳过当前正文读取的依据。

#### Scenario: 连续追问后上下文失去正文

- **WHEN** Agent 已读 Skill，随后用户连续追问并在会话恢复或压缩后继续相关任务
- **THEN** Agent 可在相同路径和 revision 的完整正文仍可用时复用，正文或版本证据缺失时从当轮清单路径重新读取

#### Scenario: 更新正文或切换 Agent

- **WHEN** Skill 更新或实际执行 Agent 切换，且上下文中仍有旧正文
- **THEN** 请求提供新解析结果并要求在路径或 revision 变化或无法确认上下文中版本时重新读取

#### Scenario: 从当前范围移除部分 Skill

- **WHEN** 用户取消勾选一个此前已经读取的 Skill，且保留其他勾选项
- **THEN** 后续请求只允许加载或复用仍在当轮范围内的 Skill

### Requirement: 命令保留显式展开和直属 Skill 加载

Dext SHALL 按实际执行 Agent 解析 `/command` 所属的已勾选 Skill，并按现有规则展开参数。在按需模式下，命令所属 Skill SHALL 直接加载全文一次，其余可用勾选项 SHALL 以简短清单提供。Plan 跟进请求 SHALL 继续携带当前用户回合已展开的命令与其适用的 Skill 指令，并保留原有 Plan 协议。

#### Scenario: 已勾选多项 Skill 后运行命令

- **WHEN** 按需会话勾选 A 与 B 后输入属于 A 的 `/command` 和参数
- **THEN** 命令参数按原规则展开，A 的正文在展开命令前直接发送一次，B 只进入清单
- **AND** 用户的下一条普通请求恢复按需语义

#### Scenario: 运行未选中的命令或命令所属 Skill 缺失

- **WHEN** 命令所属 Skill 未被勾选、没有当前可用版本或其正文不可读
- **THEN** Dext 反馈原因并使该显式调用失败

#### Scenario: 一次 Plan 执行产生后续请求

- **WHEN** 带显式命令的 Plan 执行因进度或验证进入同一用户回合的后续请求
- **THEN** 已展开的命令继续可用，命令所属 Skill 按该回合既定策略直接加载，任务状态、验证与结束条件按原有协议处理

### Requirement: 其他入口保留各自的 Skill 契约

脚本 API 的 `ask`、`plan`、`agent` 和 `template` SHALL 在每次调用解析并按既有顺序直接加载显式 `skills` 和 `rules` 的全文，维持规则、语言和模板输出约束的既有优先级。显式选择 MUST 仅在本次调用中生效，并沿用原有资源定位、路径校验、信任、权限和读取失败行为。`skill()` SHALL 保持直接调用语义。Code 普通输入和资源草稿 MUST NOT 使用会话勾选项生成清单或注入正文。

#### Scenario: 脚本调用与对话勾选不同

- **WHEN** 会话勾选 A，用户通过 Code 调用 `template` 且显式传入 B、C 和有序规则
- **THEN** B、C 正文先于规则，模板输出约束保留原位置，A 不因会话勾选被注入

#### Scenario: 连续脚本调用选择不同规则与 Skill

- **WHEN** 两次独立调用分别选择不同规则及 Skill，随后的调用省略选择
- **THEN** 前两次调用仅加载各自所选的全文，后一次调用不再收到先前选择的正文
- **AND** 固定说明的交付方式不改变该调用范围

#### Scenario: 显式资源不可读取

- **WHEN** 脚本调用显式指定的规则或 Skill 缺失、不可读或未通过原有信任或路径校验
- **THEN** Dext 保留原有错误行为，结构化任务不予派发

#### Scenario: Code 普通输入与资源草稿

- **WHEN** 用户在勾选 Skill 的会话发送普通 Code 输入，或从对应资源入口生成草稿
- **THEN** 请求继续遵循各自的生成或执行流程，且不携带会话勾选产生的 Skill 清单、正文或斜线命令展开

### Requirement: 按需读取保持现有权限并反馈不可用

按需读取 SHALL 优先使用当前后端已有的文件工具，并维持工作区信任与 Ask 的只读权限。可选宿主读取入口仅在确认原生读取缺口时提供，且 MUST 限于当前受信任会话已勾选 Skill 的当前版本及其 `SKILL.md`。系统 SHALL 反馈缺失、不可用或读取失败的原因。

#### Scenario: Ask 在受信任工作区读取项目 Skill

- **WHEN** Ask 中的任务需要某个已勾选的项目 Skill 且当前上下文缺少正文
- **THEN** 可用的原生文件工具读取清单路径，Ask 保持只读

#### Scenario: 普通按需项没有可用文件

- **WHEN** 某个所选 Skill 的文件缺失或版本不可用可在派发前确定
- **THEN** Dext 提示该 Skill 的 ID 和原因，其他可用勾选项和普通请求继续可用

#### Scenario: 派发后读取失败或工具不可用

- **WHEN** Agent 尝试读取相关 Skill，读取失败、工具不可用，且没有已授权的读取途径
- **THEN** 回复说明相关 Skill 和失败原因，不声称已按该正文执行，可独立完成的部分仍可继续

#### Scenario: 宿主读取工具拒绝越权或过期请求

- **WHEN** 已启用的宿主工具收到未勾选的 ID、过期回合、其他会话或不受信任工作区的读取请求
- **THEN** 工具拒绝读取且不返回文件正文

### Requirement: 普通对话固定说明使用会话指令

Ask、Plan 和 Agent SHALL 通过当前后端及会话路径支持的原生追加入口交付 Dext 固定的语言与格式说明、Lazy 范围及读取规则。系统 SHALL 保留用户已配置的附加提示和后端默认工具说明。Dext 提升到系统或开发者指令层级的内容 MUST 仅包含自身生成的固定规则及已解析的偏好。

#### Scenario: 通过原生入口续聊

- **WHEN** 当前后端能在新建或续聊时可靠地提供原生固定规则
- **THEN** 固定规则由原生指令生效，Dext 的当轮用户消息无需携带固定正文
- **AND** 进程重启后可按后端协议重新交付启动配置，后续用户消息无需为此追加固定正文

#### Scenario: 当前会话路径缺少可靠原生入口

- **WHEN** 后端或版本无法可靠承载某段规则，或恢复、分叉后无法确认该规则存在
- **THEN** Dext 按该段规则使用精简内联回退，并确保同一请求中每段规则只有一份生效来源
- **AND** 依照原有会话语义保留历史，用户已配置的附加提示和默认工具说明继续生效

#### Scenario: 普通请求含当轮数据

- **WHEN** 用户选择 Skill、运行命令或发送普通消息
- **THEN** Skill 清单、正文、命令参数与用户输入维持各自原有内容层级和信任权限
- **AND** Plan 输出协议继续随适用请求生效，已有项目、用户提示文件及已安装 Skill 文件保持原样

### Requirement: 普通对话语言偏好按当轮生效

Dext SHALL 在回合开始时确定该回合的语言偏好，并在下一回合采用新设置。用户在当前请求明确指定的语言或翻译要求 SHALL 优先，面向机器的格式、原文及代码 SHALL 保持原有约束。

#### Scenario: 回合执行期间更改语言

- **WHEN** 用户在一个回合执行期间把语言从简体中文改为英语
- **THEN** 已运行的回合及其内部跟进使用该回合的简体中文快照
- **AND** 下一回合使用英语，包括继续同一后端会话时

#### Scenario: 设置变为由请求决定语言

- **WHEN** 用户切回 `auto` 且 VS Code 显示语言无法解析为支持的语言
- **THEN** 下一回合由当前请求决定语言，已保存的 Dext 语言偏好停止生效
- **AND** 无法及时更新原生语言偏好的会话使用简短的当轮覆盖表示撤销该偏好

#### Scenario: 当前请求明确指定其他语言

- **WHEN** 用户在配置英语的会话中明确要求使用日语或交付日语译文
- **THEN** 该请求采用用户明确指定的语言，原有的格式保护继续生效

### Requirement: 脚本 API 固定说明按调用交付

脚本 API 的 `ask`、`plan`、`agent` 和 `template` SHALL 在已验证兼容的结构化派发路径中，通过后端原生入口向本次独立执行环境交付 Dext 自带的通用载荷读取说明和输出格式保护。其他路径 SHALL 使用精简内联。每段固定说明 MUST 只有一份生效来源。两种交付方式 SHALL 保留本次输出 schema、模板约束、原有结构化结果校验、后端工具权限和用户已配置的附加提示。

#### Scenario: 原生追加与结构化输出兼容

- **WHEN** 实际 API 派发路径支持原生追加，且能保留当前调用的结构化结果协议及用户配置
- **THEN** 固定说明经原生入口应用于本次执行，用户消息省去对应固定正文
- **AND** 本次调用的结果仍按同一 schema 校验，`template` 按同一字段契约渲染

#### Scenario: 结构化派发使用精简内联

- **WHEN** API 路径缺少可靠原生入口，或原生方式无法保留当前的结构化结果协议或用户配置
- **THEN** 本次调用使用精简内联固定说明，保持原来的 schema、校验和模板渲染行为
- **AND** 装载失败时只有在任务尚未提交的情况下才可切换交付方式
