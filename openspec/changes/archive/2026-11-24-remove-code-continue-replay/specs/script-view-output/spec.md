# Spec Delta

## ADDED Requirements

### Requirement: 重新执行 Code 轮次使用当次调用结果

Code 轮次 SHALL 通过现有「重新执行」流程重跑。确认提示 SHALL 说明写入操作可能再次发生。用户确认后，系统 SHALL 用原输入和原模式按现有规则在同一会话启动一个新轮次，从头执行脚本，并将本轮实际产生的 Dext API 响应交给脚本。原轮次及已产生的可见输出 SHALL 保持可查看。

#### Scenario: 确认重跑产生新输出

- **WHEN** Code 脚本成功完成一次 API 调用、产生可见输出后失败，用户在原轮次确认「重新执行」
- **THEN** 新轮次从头执行，先前成功的调用再次发生，后续脚本逻辑收到本轮的新响应
- **AND** 本轮输出写入独立的轮次记录，原失败轮次仍显示原有错误和已保存输出

#### Scenario: 取消重跑确认

- **WHEN** 用户关闭或取消「重新执行」确认
- **THEN** 系统不执行脚本，也不创建新轮次

## MODIFIED Requirements

### Requirement: 只读显示结果可在历史恢复

显示结果 SHALL 保存经验证的树数据，在实时回合和历史中使用等价的组件结构。宿主 SHALL 禁用脚本树的状态修改和复制控件。恢复会话或打开 History 时，已有回合与交互应答 SHALL 从已保存的记录呈现。

#### Scenario: 重放显示结果

- **WHEN** 用户恢复会话或在 History 打开一个已记录两次显示调用的轮次，包括在显示完成后失败的轮次
- **THEN** 两个输出仍按记录顺序各出现一次，结构和文本一致
- **AND** 脚本树的 CodeBlock 复制按钮保持原生禁用，且不会产生任何脚本回调

### Requirement: 报告后的交互通过已有 UI 方法返回

脚本 SHALL 能先等待只读报告完成记录，再使用现有 `ui.form`、`ui.confirm` 或快捷交互方法取得结果。现有参数、返回值、默认挂载位置、取消和中止语义 MUST 保持兼容。历史中的已回答交互 SHALL 按现有规则显示为静态摘要。

#### Scenario: 脚本消费用户提交

- **WHEN** 检查报告已追加，脚本等待 `ui.form`，用户选择修复范围并按下确认动作
- **THEN** 脚本收到 `status: "submitted"`、按字段 ID 索引的 `answers` 和所按的 `action`，并可按结果决定后续步骤
- **AND** 报告保持只读，在 History 中同一次应答以静态摘要显示

#### Scenario: 取消和重放按既有路径处理

- **WHEN** 用户关闭表单、取消确认、停止回合，或打开此前已完成的历史
- **THEN** 表单按既有设置返回取消结果或中止，确认在返回模式下得到 `confirmed: false`，停止按既有中止路径处理
- **AND** 打开历史或通过 Continue in Dext 恢复会话时，已记录的应答以现有静态摘要呈现，不再请求应答
