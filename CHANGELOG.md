# Changelog

## UI interaction unification

- Added `ui.select`, `ui.radio`, `ui.checkbox`, `ui.form`, and `ui.alert`, with shared fields and inline/dialog presentation for workflow and Agent questions.
- Kept `ui.input` and `ui.confirm` results and cancellation semantics; added scoped requests, non-secret draft restoration, accessible dropdowns and bounded history summaries.
- **Breaking:** removed `ui.choose`, its host/response protocol and `UiChoiceResult`. Replace calls manually with `ui.radio`, `ui.checkbox`, or `ui.select`; each returns its own result type. Existing history remains readable through a generic fallback and cannot resume a removed interaction.

All notable changes to Dext are documented in this file.

## Unreleased

- List the `skills` and `rules` a conversation API accepts in the generated declaration. Both fields are `internal`, because Dext never forwards them to a provider as control fields, so the declaration generator dropped them along with every other runtime-only field — but `ask`, `plan`, `agent` and `template` document them as per-call options, the runtime loads them (`.dext/rules` files are injected into the Agent instruction, skills first and rules last), and the resource panel and the reference signature already showed them. A caller had to spread an untyped object into the options to pass one, which is what a migrated ADR API needed for `rules: ["adr-update.md"]`. `.dx` had this right: its language service listed those two fields for exactly those four APIs, and that special case went with the `.dx` removal while `dextOptionsType` kept filtering unconditionally. The printer behind it was the `.dx` signature renderer `formatMethodSignature`, and with no caller left it is deleted along with its `includeInternal` option, so `test/methodSignature.test.ts` now covers the parameter, field and result-type renderers that the resource panel and the declaration still call. The rule now lives once, as `CONVERSATION_METHODS` in `methodSignature.ts`, and the declaration, the reference signature and the resource panel all read it, so `await agent({ input: "…", rules: ["review.md"] })` type-checks. `test/dextTypes.test.ts` asserts those four signatures carry `skills?: string | string[]` and `rules?: string | string[]` and that no other API does, and `docs/workflows.md` and its Chinese translation record it.

- Declare the Node type definitions the generated project needs, in the manifest Dext already owns. `.dext/package.json` carried `"type": "module"` and nothing else, so a workspace whose API file imports a Node built-in — `import fs from "node:fs/promises"`, the documented way to read or write a file now that the `node.fs` bridge went with `.dx` — had nowhere to declare `@types/node`: a dependency added to that file was dropped by the next **Dext: Reload APIs**, and a workspace with no manifest of its own has no other place to put one. The generated manifest now declares `"@types/node": "^22"`, pinned to the Node major the kernel runs, and `npm install` in `.dext` installs it. That alone does not resolve the import: the generated project sets `types: []` so an unrelated `@types/*` in the workspace cannot leak globals into these files, which also keeps `@types/node`'s ambient modules out of the program until a file asks for them, so a file that imports a Node built-in starts with `/// <reference types="node" />`. `docs/workflows.md` and its Chinese translation record both steps, the two READMEs no longer describe the manifest as an ESM marker alone, `test/dextTypes.test.ts` pins the generated content, and `test/extensionHost.ts` asserts that a reload writes it.

- Leave Ctrl+C to VS Code wherever VS Code already copies, and take only what Dext needs. Two bindings still replaced native behavior. In a terminal, `ctrl+c` — Control+C on macOS, where the native copy is Cmd+C — and Windows' `ctrl+shift+c` ran a Dext command the terminal never skips the shell for: VS Code only runs a keybinding there when its command is in `terminal.integrated.commandsToSkipShell`, so the key reached the shell as well, and copying output with Ctrl+Shift+C interrupted the running command. Dext now claims only `ctrl+shift+c` (`cmd+c` on macOS), the chord VS Code itself copies with, and contributes `dext.copyTerminalSelectionWithContext` to `commandsToSkipShell` so the terminal runs it instead of typing into the shell; plain Ctrl+C keeps sending the interrupt. In an editor, Ctrl+C with several cursors copied only the primary selection — `selectionAttachment` reads `editor.selection` — and Ctrl+C with nothing selected replaced VS Code's copy-line behavior. A multi-cursor copy is now left entirely to VS Code (both the keybinding and the command, so the context menu cannot regress it), and a file editor without a selection runs `dext.copyFilePathWithLine`, which stages the path and then lets `editor.action.clipboardCopyAction` put the line on the clipboard. The staged paths are keyed on the text the native copy leaves behind, so only the copy that staged them can consume them. `test/attachmentStore.test.ts`, `test/vscodeClipboardFiles.test.ts`, `test/sidebarClipboard.test.ts`, `test/packageManifest.test.ts` and the live host test cover the staging, both native restores and the multi-cursor copy, and `docs/workflows.md` records the split.

- Keep Explorer file copies pasteable as files. `dext.copyFilePathOnCopy` rebound Ctrl+C in the Explorer to VS Code's `copyFilePath`, which replaces the clipboard with the path text — and an Explorer paste reads only VS Code's own file list (`code/file-list`) or a native `FileList`, never clipboard text — so copying a file and pressing Ctrl+V in another window's Explorer silently did nothing, and the Explorer's own Paste menu stayed disabled. The Explorer now runs `dext.copyFilePathWithFiles`: Copy Path supplies the text Dext Input turns into references, `AttachmentStore` stages those paths for the paste that would have read them, and VS Code's built-in `filesExplorer.copy` puts the file list back on the clipboard last, so the copied files stay pasteable in this window or another. Open Editors, editor tabs and a file editor without a selection keep the text-only path behavior, where no equivalent file-list command exists. `test/attachmentStore.test.ts`, `test/vscodeClipboardFiles.test.ts` and `test/packageManifest.test.ts` cover the staging, both paste purposes and the bindings, and `docs/workflows.md` records the change.

- Highlight a Code turn's source in the conversation, and finish painting the active theme in the composer. A turn's input was rendered as a plain `<pre>` — the colors it was written in were thrown away — so it is now colorized by the same TypeScript grammar and Monaco theme as the composer, with the file-reference chips left exactly where they were and the copy button still using the authored string. That theme was also incomplete: `vscodeTheme` mapped only the token types it knew by TextMate name, and Monaco's TypeScript tokenizer emits `identifier` for every name and `delimiter`/`delimiter.bracket`/`delimiter.parenthesis` for braces, parentheses and semicolons, so those kept Monaco's own default colors while `import` and the string took the user's — the composer beside the editor looked like a different theme. The mapping now covers them, and carries each rule's `fontStyle` (italics, bold) as well. `test/monacoThemeRules.test.ts` and `test/vscodeTheme.test.ts` cover the mapping, the browser labs assert that a name and a brace take the applied theme's colors and that a Code turn's input is colorized, and `docs/workflows.md` records both.

- Keep the composer's completion in Code mode. The provider was registered for the composer's URI scheme alone, and the scheme does not change with the mode, so typing a prompt in Agent, Chat or Plan mode offered `mcp` and `McpRawResult` with an auto-import — TypeScript symbols in a plain-text box. The selector now names the language as well (`typescript`, which is what Code mode gives the model and nothing else does), the live Webview harness asserts the selector and the browser lab asserts that Chat mode offers no symbol, and `docs/workflows.md` records that completion, hover, parameter help and diagnostics belong to Code mode.

- Keep a Code run open while it is waiting for a Dext API. A buffer that called an API without `await` — `commit()` instead of `await commit()` — ended the run as soon as the module body finished, which is *before* the extension had executed the call: the turn was marked complete, the panel stopped showing activity, and the agent the call had started kept working invisibly (and its failure landed where nothing was listening). The kernel now waits for the calls a run left in flight before reporting it, and a floating call that failed fails the run. Nothing is reported about a call that simply was not awaited: it is ordinary TypeScript, the editor's types already show it returns a promise, and Output does not need to repeat it. `test/dextHost.test.ts` covers a floating call that is still running when the module ends and one that fails, and `test/dextKernelBundle.test.ts` and the asset check cover the same through the built kernel, where a bundled copy of the runtime would keep its own in-flight registry.

- Report this extension's real version in the CLI handshakes. The Codex App Server handshake sent a hand-written `version: "0.1.2"` and the Harness handshake sent `"1"`, so the client a CLI logged or displayed could disagree with the extension a user actually has installed, and every release had to remember to edit those literals. Both now read `name`, `displayName` and `version` from the extension manifest — the same fields a user sees in the Extensions view — which is what `src/core/mcpRegistry.ts` already did for its own handshake. `test/codexConversationRunner.test.ts` asserts the App Server is told that name, title and version.

- Give the composer the TypeScript language it claims to use. `monacoEnvironment` imported Monaco's Python grammar but never the TypeScript one, and Monaco silently replaces an unregistered language id with `plaintext` (`LanguageService._createAndGetLanguageIdentifier`), so the composer's model was never TypeScript at all: rich language features were requested for `plaintext`, the TypeScript contribution's `onLanguage("typescript", …)` listener never fired, and `getTypeScriptWorker()` rejected with "TypeScript not registered!". No completion, hover, squiggle, signature help or F12 could appear, whatever the mode badge said — this, not the mode switch, is why Code mode stayed silent. Importing `languages/definitions/typescript` gives the model a registered language and the editor a working TypeScript service; the live Webview harness now asserts the model's language in both modes, the worker's answers, the `dext/api/*` mapping against the generated project, and that an unimported export is offered with its import while a directory name is not offered at all. The Monaco lab behind `npm run check:ui` now asserts the same in a browser — parameter hints for a declared signature, a diagnostic for an export the declaration does not have, and accepting `commit` from the suggest widget writing its import — after it turned out to bundle two copies of Monaco (the lab's own `main.ts` resolved the lab's nested install while `src/` resolved the repository's), which had left the lab unable to see any language feature at all.

- List the Node and JavaScript API reference in **Dext: View APIs**, generated from the declarations rather than written by hand. The `.dx` removal took the `node.*` and `js.date` bridges with it, so the API panel listed only the callable Dext APIs even though Code mode runs real Node and the ECMAScript library; a reader had no way to see what `import fs from "node:fs/promises"` actually offers. `scripts/generateApiReference.mjs` now reads the declarations through the TypeScript compiler — the ambient `node:` modules and globals of `@types/node` for the `node` group, and the globals of TypeScript's own `lib.es*.d.ts` for the `js` group — and writes `dist/api-reference.json`: 55 Node modules, 71 Node globals and 61 ECMAScript globals, each with every member's own signature, JSDoc, `@param`, `@returns`, `@deprecated` and `@example`. The catalog is a build artifact (`esbuild.mjs` writes it, `npm run check` runs `generateApiReference.mjs --check` against it), the APIs page reads it lazily and shows `node` and `js` beside Top level, and a reference entry opens a detail page with every member expanded instead of a source file: it is documentation for what code may import, not a callable Dext API, so it offers no Insert reference and its specifier line has a Copy button that goes through `vscode.env.clipboard` instead of the Webview. A build without the catalog shows the callable APIs alone. `test/apiReference.test.ts` covers the parse boundary, the entry mapping, the rendered member documentation and the copy path; `docs/workflows.md` and its Chinese translation record the same split.

- Resolve the workspace's own APIs in the composer, keeping Code mode plain TypeScript. Monaco has no filesystem, so the composer only ever had the generated `dext` declaration: `import { main } from "dext/api/git/commit"` — the documented way to call a project API — was a `Cannot find module` error there with no completion, even though the kernel resolved it. The workspace's `.dext/api` sources now travel to the composer as virtual files and are resolved by the same `dext/api/*` mapping the generated project gives VS Code, so a project API completes, hovers and type-checks in the composer exactly as it does in `.dext/api/*.ts` (bounded to 200 modules / 2 MB, refreshed on every API reload). Monaco's TypeScript worker then completes without `includeCompletionsForModuleExports`, so on its own it never reports a symbol that is not already in scope, and typing `ask` or `commit` offered nothing at all; the composer now offers an unimported export together with the import that binds it — `ask` → `import { ask } from "dext";`, the workspace's `commit` → `import { commit } from "dext/api/git/commit";` — and, inside `import { … } from "…"`, that module's exports alone with no edit. The names are read out of the declaration and the API sources, never guessed from a name's shape, so `.dx`-style completion and its quick fix stay gone and typing `git` — a directory, not an export — completes nothing. What remains is the runtime's own help when a run forgets an import: `git is not defined` → `use: import { main as commit } from "dext/api/git/commit";`, `ask is not defined` → `import { ask } from "dext";`. `docs/mcp.md`'s examples also gained the `import { mcp } from "dext";` they were missing.

- Map the API directories a project configures. The kernel resolves `dext/api/<id>` against `.dext/api` plus the project's own `paths.apiDirs`, but the generated `paths` project only named `./api`, so an API the project keeps elsewhere was `Cannot find module 'dext/api/…'` in the editor while the kernel imported it without complaint — the same disagreement the `./api/*` substitution used to cause, one directory over. The configured directories are now mapped relatively from `.dext/` (`../tools/api/*.ts`), which keeps the files portable; the `dext.apiDirs` setting and APIs in Dext's global storage stay unmapped on purpose, because a committed file cannot name them. `scripts/generateDextTypes.mjs` reads the same `project.json` `apiDirs` for `--workspace`, so `--check` and the extension keep writing the same text.

- Type only what the manifests actually say, and never emit a name that is not a type. Reviewing the new MCP surface turned up three ways the generated declaration could describe something the runtime does not: two tools whose server and tool names concatenate to the same identifier (`a-b` + `c` and `a` + `b-c` both render `ABCResult`) shared one interface, so one was declared with the other's fields — a colliding name is now qualified with the tool id (`ABCResultMcpABC`); a manifest whose names are all digits (`1` + `2` → `12Result`) was emitted verbatim, which is not an identifier, so the committed declaration could not compile — such a name is prefixed (`Mcp12Result`); and a tool declared by two directories was declared twice, which emits a duplicate member — ids are deduplicated first-wins, as the loader and runtime resolve them. `test/dextTypes.test.ts` covers all three, the last two against a real `tsc`.

- Replace the cached kernel when the workspace folder changes. The host is built around one root — the child's working directory, the root the loader resolves APIs against, and the directory a run's buffer is written to — and switching folders in one window left a run executing against the previous root and writing its buffer into the previous workspace's storage. The host now reports `busy()`, and the extension replaces it only when no run is in flight, so a reload still cannot kill one. The generated files are also compared line-ending agnostically: they are committed, and `core.autocrlf` handing them back as CRLF is not a reason to call them out of date or rewrite them on every reload.

- Generate the workspace's `dext` project **into the workspace**, and commit it. The generated files are the mapping the editor actually uses, so keeping them out of the repository had a cost that outweighed the saved bytes: pointing the mapping at Dext's own storage made it an absolute path (a relative `paths` entry cannot cross drives on Windows), which no teammate and no CI job could use, and every project carried a different one. A workspace that writes an API module now gets `.dext/api/dext.d.ts`, `.dext/tsconfig.json` (mapping `dext` at the relative `./api/dext.d.ts`) and `.dext/package.json`, all written and refreshed on every API reload. Every path in them is relative, so they can be committed and type-checked on any machine with no Dext installed — `Dext: Write TypeScript Types into Workspace` is gone because there is no longer a layout to choose. Every one of the three is regenerated whenever it drifts from what this version of the extension writes, which is what repairs a project generated by an earlier version (an absolute storage mapping, or a `paths` substitution that no longer resolves); a tampered declaration, project file or `package.json` is put back by the next **Dext: Reload APIs**. `npm run check` adds `generateDextTypes.mjs --workspace . --check` for this repository's own committed `.dext/`, and `dist/dext.d.ts` stays the shipped, CI-verified copy of the built-in surface. `test/extensionHost.ts` drives all of it in a live window: it asserts the three files exist, that the project carries no machine path, that a drifted project is repaired, and that the project's own MCP manifest reaches the declaration.

- Type a project's own MCP tools. The generated declaration described only the built-in surface, so `mcp.<server>.<tool>` was an index signature returning `McpRawResult`: `mcp.docs.read({ uri }).content` was an editor error even though the runtime returned exactly that, and nothing about a configured server reached completion or hover. A workspace's own `.dext/mcp/*.jsonc` manifests now take part in its declaration, nested by the id's own segments — which is how the runtime resolves a call, by joining the property names it was reached through — so each tool returns the result interface its `outputSchema` declares (with the `kind` discriminant the runtime adds), a tool named `b.c` is called as `mcp.docs.b.c`, a node can be both a tool and a step, and a tool without an output schema returns `McpRawResult`. The argument object stays `Record<string, unknown>` on purpose: its parameters cannot be narrowed while the same declaration keeps a globally configured server callable (an index signature beside a narrower member is TS2411), so each tool's contract rides its hover text (`Arguments: uri: string, limit?: number`) and the runtime remains the authority that refuses a missing or unknown argument by name. A server only a global manifest declares is walked the same way and typed as the whole `DextResult` union, which now includes the project's generated result interfaces. Only project manifests participate, because the declaration is committed: a global manifest lives on one machine and would make the file differ for everyone else. `test/dextTypes.test.ts` type-checks real consumers through a real `tsc` — the declared field resolves, a nested tool resolves, a field the manifest does not declare fails — and the live host test writes a manifest and reads the tool back out of the generated declaration.

- Write the composer's Code buffer into Dext's storage instead of the workspace. The kernel imports a real file, so a run buffer has to exist on disk, but it is an implementation detail rather than project content: `.dext/runs/run-<timestamp>-<n>.ts` put one new file in the repository on every Code run, which only `.gitignore` kept out of `git status` — and `.gitignore` is not something Dext can rely on. Buffers now live under `<globalStorage>/dext/runs/<workspace>/`, keyed by the workspace URI, pruned to the newest 20. A run's buffer is only needed while that run imports it, because Continue replays the recorded calls rather than re-reading the file. Update any `.gitignore` entry for `.dext/runs/` — the directory is no longer created.

- Resolve `dext/api/<id>` imports in the generated project. The `paths` substitution was `./api/*`, which matches nothing under `nodenext` module resolution — TypeScript never guesses a missing extension there — so `import { main } from "dext/api/team/analyze"`, the documented way to call another API module, was a `Cannot find module` error in every `.dext/api/*.ts` file. The substitution now names the extension, plus the two other forms the kernel loader accepts (`.mts` and a directory `index.ts`), and `test/dextTypes.test.ts` type-checks a real consumer of both.

- **Breaking:** remove the `.dx` language. Dext APIs are ordinary TypeScript modules now, so the parser, the checker with its ~98 rules, the interpreter, the language service (completion, hover, signatures, go to definition, semantic tokens, the TextMate grammar) and the `.dx` diagnostics chain it fed are all deleted: `workflow.ts`, `workflowRuntime.ts`, `workflowCheckpoint.ts`, `pythonStrings.ts`, `pythonType.ts`, `languageService.ts`, `languageHover.ts`, `apiNavigation.ts`, `builtinMemberNavigation.ts`, `dextSemanticTokens.ts`, `dextTokenTheme.ts`, `vscodeHover.ts`, `monacoLanguage.ts`, `languageClient.ts` and the `dext-api` language contribution. `customApi.ts`, `apiCheck.ts`, `apiRuleDiagnostics.ts`, `apiDiagnostic.ts` and `vscodeApiDiagnostics.ts` go with them: a custom API is a plain TypeScript module under `.dext/api` that exports `main`, the kernel imports it (`import { main } from "dext/api/git/commit"`), and Problems come from the TypeScript service instead of a hand-written checker. The four `.dx` virtual-document providers (`builtin-apis.dx`, `builtin-types.dx`, `mcp-apis.dx`) are deleted too — F12 resolves at the generated `.dext/api/dext.d.ts`. The interpreter's resource limits (100 folded items, 100 `while` iterations, `range` ≤ 100 000, import depth) are deliberately not recreated, and the old checkpoints are void: resuming is call-level replay, not statement-level. `scripts/migrateDxToTs.mjs` converts a `.dx` file (`def main(...) -> Result` → `export async function main(...): Promise<Result>`, keyword arguments → one object literal, `print(text=…)` → `console.log(…)`, `True`/`False`/`None`, `elif`, wrapped calls) and reports every construct it could not convert instead of guessing; the repository's own `.dext/api/git/commit.dx` is migrated this way. `test/apiFailure.test.ts`, `test/customApi.test.ts`, `test/mcpApiAssistance.test.ts`, `test/pythonType.test.ts`, `test/webviewLanguageClient.test.ts` and the other `.dx` suites are deleted, and `test/runtime.test.ts`, `test/builtinCli.test.ts`, `test/mcpManifest.test.ts`, `test/builtinTypeDefinitions.test.ts`, `test/historyRender.test.ts`, `test/workflowRecorder.test.ts` and `test/extensionHost.ts` are rewritten at the `InvocationAst`/generated-types level. `@lezer/common`, `@lezer/highlight` and `@lezer/python` are no longer dependencies.

- Import the result types in every skeleton and example we generate. A result interface (`AskResult`, `AgentResult`, …) is exported by the `dext` module rather than declared globally, so `export async function main(): Promise<AskResult>` only compiles when the type is imported — the `.dx` codemod, the recorder and the resource prompt all emitted the bare name, and the migrated `.dext/api/git/commit.ts` failed with `Cannot find name 'AgentResult'. ts(2304)`. They now emit `import { ask, type AskResult } from "dext";`, the shipped declaration's own header says so where F12 lands, and `test/dextTypes.test.ts` proves both directions against a real `tsc`: the skeleton we generate compiles, and the same file without the type import fails with that exact message.

- Register a recorded conversation as a TypeScript module. **History → Record workflow** wrote a `.dx` skeleton; it now writes a `.ts` module with an `import { agent, ask, ui, type AskResult } from "dext"` line, `export async function main(prompt?: string): Promise<AskResult>`, `await ask({ input: … })`, `await agent({ input: …, apply: false })`, `await ui.confirm({ message: … })` for a confirmation the conversation went through, and `console.log(...)` when there is nothing to return (`print` no longer exists). Recorded Code-mode turns stay comments, because re-wrapping them in an agent call would change what they do. The file's suggested name ends in `.ts` and the API panel lists `.ts` API modules (`dext.apiDirs` included).

- Keep the generated `.dext` project in step with the registry, and open it from the API panel. A reload writes `.dext/api/dext.d.ts`, `.dext/tsconfig.json` (`erasableSyntaxOnly`, `strict`, `nodenext`) and `.dext/package.json` (`"type": "module"`, without which tsserver rejects the top-level `await` the kernel supports), so completion, hover and F12 describe the API surface that actually exists. **Open built-in API definition** now opens that declaration instead of a `.dx` virtual document, and `dext.checkApis` is gone with the diagnostics chain it drove.

- Run Code mode as real TypeScript in a long-lived Node child process instead of an interpreter in the extension host. `src/runner/dextHost.ts` spawns the kernel (`ELECTRON_RUN_AS_NODE=1` when the extension host is Electron, `--import` of `dist/dextLoader.mjs`), handshakes over the child's IPC channel, answers each `request` by synthesizing an ordinary `InvocationAst` and running it through the existing runtime — so contract validation, MCP, `ui.*` and the Agent CLIs are reused unchanged — and turns every `request` into a recorded step. `src/runner/dextKernel.mjs` re-registers the loader with a fresh generation before each run, so every workspace module is evaluated again and module-level state cannot leak between runs; `src/runner/dextRuntime.mjs` is the `dext` module user code imports (`ask`, `plan`, `agent`, `apply`, `terminal`, `skill`, `template`, `ui.*`, `mcp.<server>.<tool>`). `console.log`/`console.error` are captured as process-output steps (`stream: { channel, text }`, merged within a tick, 64 KiB per step) and are not Dext results. Cancelling a run kills the kernel and the next run starts a fresh one; `dext.workflow.maxConcurrency` now caps how many API calls may be in flight at once (the queue lives in the host) instead of a comprehension's fan-out width. The runtime facts behind the design — measured Node versions, `--import`/`module.register()` behaviour, native type stripping, why the kernel entry must be `.mjs` — are recorded in `docs/development.md`, and `scripts/dextSmoke.mjs` proves the loop with no VS Code involved.

- Retire `print`, the `PrintResult` type and its result kind. `console.log` is ordinary process output now, so `print` had no job left, and keeping it would have shipped a first-class result type — member access, custom-API return annotations, schema, hover and type definitions — that existed only to display a line of text. `turnComponents.ts`, `historyRender.ts` and the Webview render the new `stream` steps instead (monospace, channel-labelled, outside the API-card shell), and `WorkflowStepResponse` carries `stream` as mutually exclusive with `response`.

- Trim the result kinds from 13 to 9 and drop `skipped`. `BuiltinOutputKind` is now exactly `ask`, `plan`, `agent`, `template`, `apply`, `terminal`, `skill`, `ui`, `mcpRaw`; the `node` and `js` passthrough kinds went with their bridges, `patch` was never referenced by any method (it is a field type — `AgentResult.patch` and turn reviews — not an output kind), and the `.dx` TypedDict escape hatch `(string & {})` is gone, leaving `OutputKind = BuiltinOutputKind | 'mcp.<server>.<tool>'` and an exhaustive switch in `axAdapter`. `ask`, `skill` and `template` stay separate names for one isomorphic `{kind, text}` shape (recorded as a test assertion rather than a merge, because the names are user-visible). `ExecutionState` no longer has `skipped`: a statement that never ran records no step instead of a placeholder, so the interpreter's skip bookkeeping is gone. `test/resultKindAudit.test.ts` asserts the nine kinds, the removed ones, and the isomorphism.

- Remove the `node.*` and `js.date` whitelist bridges. They existed because `.dx` had no way to call a library; the kernel runs real Node, so `import fs from "node:fs/promises"` is the supported path and the generated catalog, its policy, `builtinResultTypes.ts` and `generateNodeBuiltinCatalog.mjs` are deleted with them (`js.date` included — `new Date()` is available directly).

- Check every value that crosses the kernel/extension-host boundary. `toBoundaryJson` (TypeScript) and `dextSerialization.mjs` (kernel) refuse functions, symbols, bigints, non-finite numbers, `Map`, `Set`, `Buffer`, typed arrays, class instances without `toJSON()` and circular references with a message naming the path and the replacement, and turn a `Date` into an ISO string. `dextHost` validates each `RuntimeResponse` on the way to the kernel and each wire step on the way back, so a value JSON cannot carry fails where it was produced instead of degrading silently at `process.send`.

- Resume a failed Code run at the call boundary instead of the statement boundary. `src/runner/dextResumeCache.ts` records every API call a run makes (index, method, argument fingerprint, response); Continue hands those recordings to a fresh kernel, a call that still matches returns the recorded response without running again, and stream steps never consume an entry. Replay is only safe while the calls line up, so a mismatch — the file changed, or a value the recording cannot see (`Date.now()`, `Math.random()`, a direct `fs` read) sent the second run down another path — is a hard error rather than a response attached to the wrong call. This replaces the `.dx` workflow checkpoint: statement-level resume and the `skipped` state are gone, old checkpoints are void without a compatibility path, and the kernel's per-run module-registry reset is what keeps a reused kernel from carrying state between runs. `test/dextResume.test.ts` covers a hit, a mismatch, a non-deterministic divergence and stream alignment.
