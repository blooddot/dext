# Changelog

All notable changes to Dext are documented in this file.

## 0.1.2 - 2026-11-03

- Pi runs the packages the user installed with `pi install`: the composer's **Plugins** row chooses them per conversation and starts on all of them, a read-only turn still blocks `write`, `edit`, `bash` and `powershell`, and a read-only turn with `pi-subagents` caps its child sessions at read-only tools.

- A Plan turn's Todo panel can be driven by a tool call: Pi's `dext_update_todos` takes the same `updates`, `blocked` and `verification` object as the `dext-todo` comment, so tasks move one at a time instead of only through prose.
- The Plan Todo panel moves task by task while a turn runs: a task is reported as soon as its verify step passes, so the panel no longer stays on the first task for the whole run.
- `dext_fetch` gives read-only turns a web reader that refuses credential-bearing and loopback, private and link-local targets (re-checked on every redirect), follows at most 5 redirects, times out after 20 seconds and returns at most 512 KiB with a `truncated` flag; a GitHub file URL is read through `cdn.jsdelivr.net` with the original URL as fallback.
- Project norms are maintained from **Resources · Project** instead of the Knowledge reader, which is now read-only: an unchanged body counts as a confirmation (`accepted`/`current`) and a changed one as `edited`/`needs_verification`, with the model revision raised either way.
- Knowledge reads top-down in dependency order: the introduction's **Start here** lists every topic dependency-first and shows a one-line source-freshness summary once **Check sources** runs.
- **Build/update project model** drafts the C4 runtime boundaries again: one bounded pass records evidence-backed `person`, `system` and `container` nodes with their relations, so Knowledge shows the **Project landscape** and **Runtime units** diagrams.
- **Update project model** re-drafts only the modules whose files changed; an unchanged module keeps its saved prose and review state, and a model saved before these hashes existed re-drafts every module on its first update.
- **Breaking:** an API's entry function must be named after its file and `main` is no longer recognised. Replace `export async function main` in `.dext/api/...` with the file's own name (`.dext/api/dev/fix.ts` exports `fix`) and change `import { main as fix } from "dext/api/dev/fix"` to `import { fix } from "dext/api/dev/fix"`.
- The API **Execution flow** is now the entry function's own statements, with a decision and its two branches, a loop with its back edge, `try` as one step and an end node per returning branch; the previous call graph stays as the fallback when the entry function is missing or does not parse.
- A `break` keeps its arrow in the Execution flow: the branch that leaves a loop is wired to what follows the loop, and a `continue` returns to its loop.
- `mermaid` fenced blocks render as diagrams in every Dext Markdown output surface — the turn's **Output**, finished **Process** messages and **History** pages — while a still-streaming row keeps its source.
- A tool call that never reports a result stops the turn after thirty minutes instead of waiting forever: idle detection pauses while a tool runs, each continuous tool phase gets the full ceiling, and a shorter `dext.agent.timeoutMs` still wins.
- The Todo panel is Plan-only: Pi no longer receives a `dext_update_plan` tool, Codex's `todo_list` parsing is gone, and a normal Agent turn drops provider task-list events instead of freezing the panel on one snapshot.
- The screenshot annotation tab zooms like a picture viewer: a bottom bar carries zoom out, the scale, zoom in, **Fit**, **1:1**, the picture's pixel size and a **Hide annotations** toggle, Ctrl/Cmd + wheel zooms around the pointer, and each mark's number is a chip outside its box.
- The Project **Specs** page is gone: each module article folds in its own norm, so the same text never renders on two pages, and a saved `specs` tab restores the reader.
- The Knowledge directory groups modules under AI-named functional areas again, with short English titles that reuse the interface and code names and one recorded interface-to-code mapping per drafted body.
- The Click to expand hint on Project settings disappears once expanded, and the three identical directory hints collapse into one shared line.
- Fix the Modules reader on a wide editor: rows keep a 4px rhythm and only the selected entry is filled, the redundant On this page rail is gone, and the article uses the width the directory leaves.
- The Modules reader decides its diagram column from the width the reading surface actually has: from 1,180px the prose keeps 56% (at most 820px) with the diagram beside it, and below that the diagram follows the explanation in the article.
- Plan and `plan()` gained optional Project grounding, preflight version checks, actual-change verification and reviewed norm reconciliation; existing plans, modes and result kinds stay compatible and completed plans are retained.
- Project has native nodes, relationships and owned Knowledge bodies, explicit bootstrap routes and a backed-up legacy migration; existing data stays usable before migration.
- `project_query` is a bounded read-only Project query, also available to Pi as a scoped host callback, together with Knowledge body and relationship controls and Plan-from-Project actions.
- Conversation history lives in files: each conversation is `<storageUri>/conversation-history/<sha256>.json`, imported once from the old `dext.history*` keys, and a stored line is capped at 64,000 characters with its removed text kept under `overflow/`. **Behaviour change:** `dext.history.maxOutputLength` now defaults to `64000` instead of `200000`.
- Pi gets one result nudge before its turn settles: the shipped Pi extension hooks `agent_before_settle` and asks once for a `dext_submit_result` call with the contract's arguments, so a turn that answered in prose no longer loses its whole report to a contract error.
- The Project architecture review signals are narrower: `community-split` stays quiet for a community spanning more than 8 responsibility modules, and `module-fragmentation` measures the largest cohesive group against files that actually have a community.
- Pi CLI appears in the composer by default: `dext.agentCli` now defaults to `codex`, `claude`, `deepseek-harness` and `pi`, so **Dext: Configure Agent** can associate an installed Pi without a settings edit.
- The **Output Language** setting now applies to Code mode: `agent()` and `ask()` calls made from workflow code receive the same interaction-language instruction, and machine-readable output is never translated.
- Importing a bare GitHub repository URL now installs its latest published release instead of its default branch; the pack records `releaseTag`, `upstreamVersion` and `commit`, **Resources > Skill** groups skills by pack and shows the installed release, and **Update Skill pack** re-imports, compares and reports added or removed skills.
- **Breaking:** every Agent result patch is applied before the result is returned, and pending-patch storage, Accept/Reject cards, Inline/Split diff views and `dext.diff.defaultView` are removed. Replace a review-then-accept step with the application outcome the turn reports, and remove `dext.diff.defaultView` from `settings.json`.
- `apply()` treats an AgentResult without a patch as `unchanged` instead of throwing; a malformed patch payload still throws.
- Plan documents are structured around `Goal`, `Context`, `Design`, `Files`, `Tasks`, `Verification`, `Risks` and an optional `Out of scope`, with conditional Mermaid **Before / After** and **Execution flow** diagrams plus a prose fallback, and `Ctrl+Shift+V` previews them.
- Every Resources category is grouped by directory, not only APIs: `rules/git/commit.md` appears under **Rule > git**, skills and MCP manifests nest the same way, and MCP discovery walks `mcp/**/*.jsonc`.
- The Resources toolbar has an **Open resources folder** button that opens the directory of the current **Global** or **Project** scope, creating the root first when it has no resources.
- Project initialization has **Pause** and **Resume**: Pause aborts the in-flight step and keeps completed AI output in `.dext/project-initialization.checkpoint.json`, and Resume re-indexes and continues after the last completed stage; the checkpoint is reused only while the structure hash, index version, evidence hash, prompt and schema version and Project AI settings still match.
- The Project initialization card repaints when a run changes status, a paused run can be resumed while its aborted call is still settling, and a checkpoint left by a run that stopped before the window closed is hydrated as resumable.
- A paused Project initialization reuses finished responsibility batches whose exact model input is unchanged and reports how many were reused; only affected batches plus the reconciliation, review and overview stages are regenerated.
- **Resume** no longer discards the checkpoint when the parse cache warms up: the evidence hash excludes parse-cache counters, a rejected checkpoint names the fields that changed, and a resumed run keeps its percentage.
- Project initialization shows a determinate percentage split across indexing, AI generation and saving, never goes backwards during a run, and reaches 100 only after validation and saving succeed.
- Project initialization keeps running when its editor tab closes instead of failing with `Webview is disposed`, and renders its saved result when the page is next opened.
- Project diagrams gained **tree** and **class** kinds on the same Archify runtime, and the local structure index is now v4 with stable symbol ids, declared types, visibility and explicit `extends`/`implements` for TS/JS, Python and Rust; Knowledge derives **Structure map** and **Type map** topics from that index without AI. Caches from index v3 are rejected, so run **Build project model** or **Update project model** once after upgrading.
- The bundled Archify runtime is 3.2.0 (tag `e62275b`) and every Project IR stays valid for schema v3: each diagram declares `meta.output`, lifecycle diagrams use `mainPath` with semantic states and transitions instead of authored lanes and geometry, and delivery receipts read the new `validation` summary.
- **Breaking:** Project diagrams render with Archify only; the Mermaid branch, `projectMermaid.ts` and the reader's static fallback are removed. Replace the old Mermaid source view with the reader's **Diagram model** panel; a stored diagram needs no migration because the model is renderer-neutral.
- A DeepSeek Harness desktop installation starts through its own launcher with `--expose-internals` and `ELECTRON_RUN_AS_NODE=1`, keeps that launcher's startup log lines as stderr diagnostics, lists presets from the shipped `dsh-web-app/presets/*.patch.yml`, mounts them through the `agentPresets` registry's `select` and caches the listing until **Refresh presets**.
- Models added in the DeepSeek Harness app now appear in Dext: the launch settings merge `llm-pi-ai`, `llm-deepseek` and `agent-default-model` from `profiles/desktop/cordis.patch.yml`, with `settings.yaml` winning per field.
- A new Conversation turn starts with **Process** collapsed, matching stored History; its summary keeps the live `Thinking for …`/`Worked for …` duration with token, edited-file and command counts, and expanding it mid-run resumes following the live end.
- DeepSeek Harness context occupancy shows in **Process** as `12k/1M context` (used/window) while the turn runs and after it finishes, while Codex and Claude keep their billed token label.
- **Breaking:** DeepSeek Harness 0.1.x and its preset package are no longer supported, and the **Manage presets** menu offers only **Refresh presets**. Replace directory presets under `$DSH_HOME/.agent-presets` and any `copyHarnessPreset` call by creating and editing presets in the Harness app.
- Resources discovers file-based APIs, rules, skills and MCP manifests without importing or executing them, keeps source paths, resource IDs and creation kinds when forwarding browser actions, and drops guessed resource paths and generated-summary fallbacks.
- The terminal timeout setting now matches runtime behaviour: 120,000 ms by default and 600,000 ms maximum, with an invalid configured value falling back to the default.
- **Breaking:** the `dext.apiDirs`, `dext.skillDirs`, `dext.plan.directory` and five `dext.project.evidence*` settings are removed with their runtime fallbacks. Replace them with `paths.apiDirs`, `paths.skillDirs`, `paths.planDirectory` and `evidence` in `.dext/project.json`.
- The old Project architecture view and whole-model AI generation entry, unused method grouping, legacy knowledge validation and change tracking, and obsolete API document helpers are removed; Project diagrams use the current reader.
- **Breaking:** source-file inline completion, its settings, evaluation commands and stored feedback and memory services are removed. Remove the `dext.completion*` entries from `settings.json`; Code-mode TypeScript completion and CLI turn-completion detection remain, and existing credentials and stored completion data are left untouched and unused.
- **Breaking:** conversation Turn Review, Plan Build Review, manual Acceptance, Review presets and the conversation knowledge-adoption bridge are removed. Replace a review step with Plan's automatic final verification and the Project norm confirmation in **Resources · Project**.
- **Breaking:** the retired Project `preset` field is no longer generated and the project file's legacy `scan` scope fallback is gone. Replace `scan.roots` in `.dext/project.json` with the `evidence` include and exclude saved from Project **Overview** before indexing; other legacy `scan` fields stay as inactive data.
- `console.log` of an object renders indented JSON instead of `util.inspect`'s depth-limited `[Object]`, with `util.inspect` at full depth as the fallback for values JSON cannot carry, and `console.error` renders the same way.
- Composer file references respect the drop operation the source allows and fall back to other path formats when reading a transfer format throws; the upstream VS Code Webview drag regression (microsoft/vscode#339036) still blocks Explorer drags, so use the Attach files button.
- The generated declaration lists the `skills` and `rules` a conversation API accepts, so `await agent({ input: ..., rules: ["review.md"] })` type-checks in `ask`, `plan`, `agent` and `template`.
- `.dext/package.json` declares `@types/node` for the Node major the kernel runs, and a file that imports a Node built-in starts with `/// <reference types="node" />` because the generated project sets `types: []`.
- Ctrl+C is left to VS Code wherever VS Code already copies: Dext claims only `ctrl+shift+c` (`cmd+c` on macOS) plus `dext.copyTerminalSelectionWithContext` in `commandsToSkipShell`, leaves a multi-cursor copy entirely to VS Code, and runs `dext.copyFilePathWithLine` for a file editor without a selection.
- Explorer file copies stay pasteable: `dext.copyFilePathWithFiles` puts the file list back on the clipboard after staging the paths, so copying a file and pasting in another Explorer window works again.
- A Code turn's input is colorized by the same TypeScript grammar and Monaco theme as the composer, and that theme now maps `identifier`, `delimiter`, `delimiter.bracket` and `delimiter.parenthesis` with their `fontStyle`.
- The composer's completion is Code-mode only: the provider now names the language as well as the URI scheme, so a prompt in Agent, Chat or Plan mode no longer offers TypeScript symbols.
- A Code run stays open while it waits for a Dext API: the kernel waits for calls left in flight before reporting the run, and a floating call that failed fails the run.
- The CLI handshakes report this extension's real name and version instead of a hand-written value, so the client a CLI logs matches the extension a user has installed.
- The composer really uses TypeScript now: importing `languages/definitions/typescript` gives the model a registered language, so completion, hover, diagnostics, signature help and go to definition work in Code mode.
- **Dext: View APIs** lists the Node and JavaScript API reference generated from the declarations — 55 Node modules, 71 Node globals and 61 ECMAScript globals with their own signatures, JSDoc and examples — under `node` and `js` beside Top level.
- The composer resolves the workspace's own APIs: `.dext/api` sources travel to the composer as virtual files, so `import { commit } from "dext/api/git/commit"` completes, hovers and type-checks, and an unimported export is offered together with the import that binds it.
- The API directories a project configures in `paths.apiDirs` are mapped relatively from `.dext/`, so an API kept outside `.dext/api` resolves in the editor as well as in the kernel.
- A project's own MCP tools are typed in the generated declaration: each tool returns the result interface its `outputSchema` declares, a nested tool is called as `mcp.docs.b.c`, and a tool's argument contract rides its hover text.
- The cached kernel is replaced when the workspace folder changes, and only while no run is in flight, so a run no longer executes against the previous root.
- **Breaking:** the generated `dext` project is written into the workspace and meant to be committed, so `Dext: Write TypeScript Types into Workspace` is gone. Replace a storage-based mapping by committing `.dext/api/dext.d.ts`, `.dext/tsconfig.json` and `.dext/package.json`, which every API reload rewrites when they drift.
- The composer's Code buffer is written under `<globalStorage>/dext/runs/<workspace>/`, pruned to the newest 20, instead of `.dext/runs/` in the repository; a `.gitignore` entry for `.dext/runs/` can be removed.
- `dext/api/<id>` imports resolve in the generated project: the `paths` substitution names `.ts`, `.mts` and a directory `index.ts`, so `import { analyze } from "dext/api/team/analyze"` is no longer a `Cannot find module` error.
- **Breaking:** the `.dx` language is removed — parser, checker, interpreter, language service, TextMate grammar, `.dx` diagnostics, the `.dx` virtual documents, the `node.*` and `js.date` bridges and the `dext.checkApis` command all go with it. Replace a `.dx` file with a TypeScript module under `.dext/api` (run `node scripts/migrateDxToTs.mjs`), import it as `import { fix } from "dext/api/dev/fix"`, and expect `.dx` checkpoints to be void because resuming is now call-level replay.
- Every skeleton and example we generate imports its result types, so `export async function analyze(): Promise<AskResult>` compiles from `import { ask, type AskResult } from "dext"`.
- **History → Record workflow** writes a TypeScript module with the imports, `export async function <recording>(prompt?: string)`, the recorded `ask`, `agent` and `ui.confirm` calls and `console.log` instead of a `.dx` skeleton.
- An API reload writes `.dext/api/dext.d.ts`, `.dext/tsconfig.json` (`erasableSyntaxOnly`, `strict`, `nodenext`) and `.dext/package.json`, and **Open built-in API definition** opens that declaration instead of a `.dx` virtual document.
- Code mode runs as real TypeScript in a long-lived Node child process: the kernel handshakes over IPC, re-registers the loader before each run, captures `console.log` and `console.error` as process-output steps, and `dext.workflow.maxConcurrency` caps how many API calls are in flight at once.
- **Breaking:** `print`, the `PrintResult` type and its result kind are removed. Replace `print(text)` with `console.log(text)` in every API module and recorded workflow.
- **Breaking:** the result kinds are trimmed from 13 to 9 and `skipped` is gone from execution state. Replace a `node` or `js` result with an ordinary TypeScript import or `new Date()`, and expect no step for a statement that never ran.
- Every value crossing the kernel and extension-host boundary is checked: functions, symbols, bigints, non-finite numbers, `Map`, `Set`, `Buffer`, typed arrays, class instances without `toJSON()` and circular references are refused with a message naming the path and the replacement, and a `Date` becomes an ISO string.
- A failed Code run resumes at the call boundary: a recorded call whose argument fingerprint still matches returns its recorded response without running again, and a mismatch is a hard error instead of a response attached to the wrong call.
- A settled question card keeps every option it offered: the live and restored cards list the whole option set with the picked rows marked, keep each description, show a typed reply as its own `Other` row, and hide secret answers.
- A question card accepts more than one answer again: a multi-select answer, or a chosen option plus a typed custom answer, no longer fails validation and leaves the card submitted with nothing delivered.
- Project diagrams use the available width and height in fullscreen, scaling proportionally and restoring the previous presentation mode on exit.
- Project diagrams lay out within their renderer's own constraints: architecture sizes uniform cells and routes connections through empty gutters, data flow caps a node to the stage pitch, a sequence canvas is sized from its participants, workflow consumes columns per lane, and every builder truncates a label to the box it gets instead of failing with `Archify could not lay out this diagram within the bounded repair budget`.
- A lifecycle diagram follows its renderer's three bands: states sit by the documented contract, each terminal drops from the event state it exits, and an exit with no free column is routed by authored `via` points instead of a rejected diagonal.
- A typed DeepSeek Harness call gets a real structured-output channel: Dext publishes `dext_submit_result` over its own preset overlay, validates every submission against the call's contract and returns the validation errors as the tool's result, so the model repairs its answer inside the same turn.
- Project knowledge and diagram generation get the provider's own structured-output schema on Codex (`--output-schema`) and Claude (`--json-schema`), falling back to the conversation transport with **Native output schema unavailable** when a CLI refuses it.
- A result whose contract declares a string array is repaired instead of failing every attempt: the repair step validates with the contract itself, so a `list[str]` answer is no longer rejected by ax's own array handling.
- `template(input, source, values)` renders text from a Dext template: the template declares its fields and `format` in `dext-template` front matter, the model supplies only field values, so a section can be neither added, renamed, reordered nor dropped; the call returns `text` and writes nothing.
- Project knowledge and diagram generation validate through the same ax structured-output predictor as the Agent result boundary, so an undeclared key is dropped at its exact path and the outermost recovered JSON object is taken.
- `mermaid` code blocks render as diagrams in inline and dialog task descriptions, follow the current light or dark theme, keep expandable source, and show their source without interrupting the form when invalid.
- **View question** keeps the display state Dext is in: the view is revealed only while its Webview is not on screen, so a maximized or docked Dext no longer drops back to the default width.
- A read-only Harness `agent` turn that answers in Markdown has its message wrapped as the `agent` result and validated, with a status event reporting the fallback, so a long turn no longer aborts with no JSON object to extract.
- A collapsed disclosure no longer owns scroll range the conversation never paints: closed disclosure content is `display: none`, `html` and `body` no longer scroll vertically, and the Webview reports a one-time `Dext scroll diagnostic` when the port's range outlives its content.
- A question the turn is parked on scrolls into view: a newly appearing card moves the view and releases the follow, **Jump to latest** returns to the live end, and a repeated or replayed waiting event leaves a reader who scrolled away where they are.
- An MCP server can declare its credential as a URL query parameter (`type: query` with a parameter `name`), set only through **Dext: Set MCP Access Token** and attached on every call including the session-terminating DELETE; a rejected server now says why, and display paths mask every query value.
- A followed conversation stays at its newest output: following is the reader's intent rather than a per-batch measurement, a drag released against the track end snaps to the current height, and returning to the end by wheel, keyboard or the jump control resumes following.
- A turn is never parked on a question nothing can render: the runner requires both the answer callback and the event sink, reports that there is no Dext surface, and answers any frame it cannot render as unavailable instead of staying silent.
- The Dext question card now shows for a DeepSeek Harness `ask_user_question` and for ACP elicitation, publishing the waiting, answered and dismissed input events the Codex runner already used.
- A generic Harness `Internal error` now reports the ACP error's data payload and the process's stderr tail, and a refused stored session continues in a new session whose prompt carries this conversation's context.
- **Breaking:** the Harness **Agent preset** menu lists exactly the installed catalog, with no Dext-only **ACP default** entry. Replace an empty preset selection with **Standard**, which every Harness conversation now mounts.
- Codex `config.toml` is parsed with `smol-toml`, so comments, sections and string escapes no longer break CLI path and model defaults.
- `agent(patch=false)` returns text-only previews without a patch, Agent result parsing goes through one tolerant boundary with one bounded repair attempt, and a failed parse stays diagnosable instead of throwing a bare invalid-JSON error.
- Project knowledge is stored in `.dext/project.json`, `.dext/objects/*.json` and `.dext/architecture.json` with independent source, confirmation, validity and ownership dimensions, and a legacy `status` field is migrated on read.
- Project, API, Global Resources and History editor tabs sit behind stable keys and versioned state: one panel per key, a page restores its own page and target after a window reload, and the Project tab exposes only Overview, Knowledge and Diagrams.
- **Breaking:** the source scanner and the per-format diagram adapters (draw.io, Mermaid, Structurizr) are removed. Replace scanned knowledge with a user-triggered **Build project model** run over a bounded, redacted evidence package, and export diagrams as HTML or SVG only.
- Project has a **Diagrams** page that embeds the Archify viewer in a sandboxed frame: select a saved diagram, generate or update one from a requirement, refresh, export HTML or SVG, go fullscreen, and see validation, version and evidence coverage; a failed render keeps the last successful result visible.
- `.dext/architecture.json` may carry `diagramId` and `rules` (`deny`, `allow`, `no_cycles`) over stable Project node ids, and the Diagrams page lists the violations the saved diagram currently has.
- The last successful render of each diagram is kept in `.dext/diagram-history.json`, newest first, so a failed render still shows the previous result after a window reload.
- The API directory and Global Resources moved out of sidebar dialogs into editor tabs, with search, namespace grouping, detail, reference insertion, source jumps, categories and refresh preserved, and `dext.editResource` opens the same flow.
- MCP tools are filed under **MCP** on the Resources page, nesting each server the way the API page nests namespaces, with per-node counts and remembered collapse state.
- `dext.viewMcp` is now `dext.viewResources` (**Dext: View Resources**) beside `dext.viewApis`; a keybinding or menu entry bound to the old id must use the new one.
- `ui.form` can declare several submit buttons through `actions`, each with its own `id`, optional `primary` highlight and `requires` list of fields it needs, and the pressed button comes back as `action`.
- Workflow and Agent interaction cards and dialogs are restyled: scrollable descriptions, selectable option rows, a pinned borderless close button, a separated action bar and a distinct primary button.
- The composer shows the Claude CLI default model configured through `env.ANTHROPIC_MODEL` in `settings.json`, and displays configured slugs such as `claude-opus-5` under their composer alias.
- Dext defaults to the Secondary Side Bar while preserving user-customized view locations, and requires VS Code 1.106 or newer.
- Codex conversation questions render as inline Dext cards above Process, with choices, custom answers and submission status; App Server drives interactive conversations, supports blocking and asynchronous questions, and closes stale requests on completion or cancellation.
- A Plan execution continues across Agent turns with round checkpoints and a separate final verification, and live and restored history show incomplete, blocked and user-stopped outcomes.
- Active Codex, Claude and DeepSeek Harness turns run beyond one hour: the default is an activity-based idle timeout with an optional total time limit and distinct timeout messages.
- Project initialization keeps its Project AI call when a provider rejects a replayed thinking block it never returned: the retry runs the same read-only stage without thinking and reports **Thinking could not be replayed** instead of failing the run.
- `ui.select`, `ui.radio`, `ui.checkbox`, `ui.form` and `ui.alert` are added, with shared fields and inline or dialog presentation for workflow and Agent questions.
- **Breaking:** `ui.choose`, its host and response protocol and `UiChoiceResult` are removed. Replace a `ui.choose` call with `ui.radio`, `ui.checkbox` or `ui.select`, each returning its own result type.

## 0.1.1 - 2026-09-09

Initial release.

- Clarify the Marketplace summary with supported agents and reusable workflows.
- Add a sidebar name, icon, and focus command declaration.
- Remove redundant activation events generated automatically by VS Code.
- Read MCP client identity from the extension manifest and centralize protocol versions for stdio and HTTP.

- Add DeepSeek Harness 0.1.2-rc.1 as the third Agent backend over ACP SDK 1.4.0, with model discovery, bound resumable sessions, permission scopes and typed workflows.
- Remove AIOA/CDP integration and its dependencies without legacy conversation compatibility.

- Use PolyForm Perimeter License 1.0.1, with separate commercial licensing available by agreement. Third-party components retain their own licenses.
- Typed Dext workflow editor and built-in APIs.
- Codex and Claude Code agent profiles.
- Workspace references, custom APIs, Skills, and MCP tool calls.
- File-private typed helper functions in `.dx` APIs, with isolated call scopes and editor assistance.
- Go to Definition for `.dx` imports, API calls, aliases, and file-private helper functions.
- Preserve returns from exception handlers and report function fallthrough without executing skipped returns.
- Typed output, history, and user interaction controls.
