# Changelog

## UI interaction unification

- Added `ui.select`, `ui.radio`, `ui.checkbox`, `ui.form`, and `ui.alert`, with shared fields and inline/dialog presentation for workflow and Agent questions.
- Kept `ui.input` and `ui.confirm` results and cancellation semantics; added scoped requests, non-secret draft restoration, accessible dropdowns and bounded history summaries.
- **Breaking:** removed `ui.choose`, its host/response protocol and `UiChoiceResult`. Replace calls manually with `ui.radio`, `ui.checkbox`, or `ui.select`; each returns its own result type. Existing history remains readable through a generic fallback and cannot resume a removed interaction.

All notable changes to Dext are documented in this file.

## Unreleased

- Give a typed DeepSeek Harness call a real structured-output channel instead of only asking for JSON in the prompt. ACP's `PromptRequest` carries no output-schema field, so Harness was the one backend with no constraint at all — and the only one whose malformed answer could not be repaired (`Result repair is not available for 'DeepSeek Harness'`). Dext's own preset overlay already runs inside the Harness process, so the contract now travels over that private channel: before the prompt Dext publishes `dext_submit_result`, a first-class tool whose argument schema is the call's own contract, and the model submits through it. Arguments arrive as losslessly materialized JSON — no fence, no envelope, no `\n` escaping — and every submission is validated against the contract, with the exact errors returned as the tool's own result. That is an ordinary `Error: <diagnostics>` the model reads without ending the turn, so it repairs its answer inside the same turn at no extra CLI call, and the turn returns the validated value rather than parsing the final message. The prompt keeps the schema and the final-message form as the fallback, so a preset that restricts the tool away (Minimal allows two tools) or a model that never calls it behaves exactly as before, and a conversation turn — which has no contract to submit against — is never offered the tool. The tool is registered per typed call and withdrawn with it, before the session closes. Validated against the installed Harness: the overlay accepts a raw JSON-Schema tool definition and the agent's model sees it.

- Give Project knowledge and diagram generation the provider's own structured-output schema on Codex and Claude, instead of only describing that schema in the prompt. `ProjectAiGenerationService` still owns the answer — the ax envelope, the strict contract parse, the evidence and reference checks, and the single bounded repair attempt are unchanged — but the transport underneath it is now Codex `--output-schema` / Claude `--json-schema` rather than a conversation turn, so the answer is constrained by the provider and cannot drift into prose, a fenced block or an envelope. The one-shot structured call is read-only, carries the selected model, reasoning effort and speed plus the trusted-workspace `dext.agentCliArgs`, and streams the same progress events into the Project panel. One shared normalization makes it safe: Codex strict output requires every object property, so the optional ones travel required-but-nullable and the `null` the model answers with is restored to "absent" before validation (no Dext or Project contract has a nullable field). A CLI that refuses the schema, or simply fails to start, falls back to the conversation transport for that attempt and reports **Native output schema unavailable** with the provider's own error, so a schema one CLI build does not accept can never cost a Project initialization. DeepSeek Harness keeps the conversation transport, because ACP's `PromptRequest` has no schema field to carry.

- Add `template(input, source, values={}, skills?, rules?, workspace?) -> TemplateResult`, which renders text from a Dext template. A rule can only ask a model to follow a template, so a model that drifts changes the output's structure; here the model returns field values only and Dext renders the headings, the section order and the list markers from the template file itself, so a section can be neither added, renamed, reordered nor dropped. The template declares its fields under `dext-template` in YAML front matter (`string`, `lines`, or `enum` with `values`) and places them in the body with `{{field}}`. Every template must declare its `format` — `markdown`, `text`, `json`, `toml` or `yaml` — which is checked when the template is loaded rather than guessed from the file name; `markdown` owns the heading and blank-line rules, `text` renders literally, and `json`, `toml` and `yaml` render literally and are then parsed, so an answer whose render does not parse fails validation and gets the same single repair with the parser's own error as its diagnostic. `format` is a reserved option — `z.toJSONSchema` still sends Codex and Claude the plain field schema, and it is never offered to the model as a field. `type: lines` renders one item per line and takes a `separator` inserted between those lines, which is what lets a JSON or TOML array carry its commas without a trailing one; `optional: true` removes a placeholder line together with the heading of the section it emptied; and `values` pins the fields Dext owns out of the model's contract and wins over anything the model returns for them. The declared fields replace the fixed result schema, so Codex and Claude receive them as their native structured-output schema (`--output-schema` / `--json-schema`); the call is read-only, so an answer that breaks the contract still gets one bounded repair, and DeepSeek Harness, whose ACP protocol has no schema field, is validated against the same contract in Dext. The call returns `text` and writes nothing, so whether the result becomes a file and where it lands are the caller's decisions (`node.fs.writeFile`), and when a file name must follow a field, the caller composes it from the value it supplied through `values` — the call never declares a destination, so one template renders to any path. The template must live inside a trusted workspace, because its content becomes part of the Agent instruction.

- Validate Project knowledge and diagram generation with the same ax structured-output predictor the Agent result boundary uses, instead of a second hand-written parse/validate/retry loop. The selected CLI still receives the response schema in its prompt (a text-only CLI transport cannot carry a native `response_format`), so ax owns the answer envelope and the bounded repair attempt: the strict contract parse and the evidence checks run as its validation step, a rejected answer is re-prompted with those diagnostics and keeps its own message (`invalid semantic model` against `evidence or references could not be verified`), and a CLI failure is reported with its own reason, diagnostics and code rather than ax's "unable to fix validation error" wrapper (a provider failure keeps its retry, cancellation, timeout and budget failures stay terminal). ax's output field is deliberately opaque: attaching the nested contract made ax walk it and JSON.parse the elements of every array-typed leaf, so an ordinary `goals: ["…"]` died inside ax before the contract was ever checked. Two other long-standing failure modes disappear with it: a key the contract never declares (a free-text `note` on a diagram node, for example) is dropped at its exact path before validation instead of refusing an otherwise verifiable answer, and the answer is taken as the **outermost** recovered JSON object, so a project model whose diagrams each carry their own `kind` is no longer mistaken for the diagram it contains. `project-knowledge-5` / `project-diagram-3`.

- Render Mermaid code blocks as diagrams in inline and dialog task descriptions, including flowcharts and class diagrams. Diagrams render locally under the Webview security policy, follow the current light/dark theme, and retain expandable source; invalid diagrams show their source without interrupting the form or other diagrams.

- Keep the display state Dext is in when **View question** is clicked. The notification focused `dext.sidebar.focus` before every question, and asking the host to reveal a view that is already on screen re-runs the Dext view's reveal path: on a maximized Secondary Side Bar — the README's fullscreen layout — Dext dropped back to its docked width on the right, so answering a question always cost the reader the layout they had chosen. The view is now revealed only while the Webview is not on screen (`WebviewView.visible`), so an on-screen Dext keeps its maximized or docked display, the conversation and the question card still arrive, and the card's first field is focused inside the Webview either way. `test/sidebarInputNotifications.test.ts` covers the on-screen and the hidden case.

- Stop discarding a whole Agent turn when the DeepSeek Harness answers in Markdown. The Harness has no native output schema, so Dext could only ask for a `{ "kind": "agent", "text": "…" }` envelope in the prompt, and the project rules carried in the payload's `instruction` field outranked that trailing reminder; a 35-minute `dev.plan` task-list turn then aborted with `No 'agent' JSON object could be extracted` and `Result repair is not available for 'DeepSeek Harness'`, losing all of its work. A read-only `agent` result that is not JSON is now wrapped as `{ kind: "agent", text: <raw message> }` and validated against the same contract, so `agent.text` stays exactly the message the model wrote; a visible "fell back to plain-text wrapping" status event reports each occurrence, a wrapped result that fails the contract still reports the original parse diagnostic, and every other kind (`ask`, `plan`, `skill`, `apply`, `codeRef`) plus every write-enabled `agent(apply=true)` turn keeps failing exactly as before. The Harness prompt also states the JSON-only envelope before *and* after the payload, with the escaping spelled out (`\n` for newlines, `\"` for double quotes, nothing outside the object), so a long session cannot lose the requirement to the rule text above it.

- Show the question the turn is parked on. A question card renders in the turn body *above* the Process timeline, and a live turn grows that timeline far past the viewport while the reader follows the newest output, so a published question could sit thousands of pixels off screen: the Harness tool call was waiting for an answer, the transcript showed nothing to answer, and the turn looked frozen until it was cancelled - which then reported `ask_user_question was aborted before the user answered`. The previous fix published the `waiting` input event correctly, which is why runner-level tests passed while the user still saw nothing: the card was rendered, just never in view. A card that newly appears while the turn is waiting now scrolls itself into view (the reader's focus lands on its first control) and releases the follow, so the next streamed batch cannot push it back out; **Jump to latest** stays available to return to the live end. Only a state that newly puts an answerable card on screen may move the view, so a repeated or replayed `waiting` event leaves a reader who scrolled away exactly where they are, and a non-blocking question the agent answers in parallel never interrupts the stream. `ui.form` and `ui.alert` requests from workflows, which park the same way, are revealed too. `scripts/checkQuestionVisibilityUi.mjs` drives the real Webview bundle through a long live turn and fails if the card is not inside the conversation viewport.

- Support MCP servers that only accept their credential as a URL query parameter. DingTalk's MCP gateway (`https://mcp-gw.dingtalk.com/server/<id>?key=<key>`) rejects both a query-bearing `url` and a `Bearer` header, so its manifest could not be registered at all. An HTTP server may now declare `auth: { "type": "query", "name": "key" }`: the url stays credential-free, the token still comes only from **Dext: Set MCP Access Token**, and Dext attaches it (URL-encoded) at request time on every call, including the session-terminating DELETE. The credential is stored under its own kind, so existing bearer and stdio tokens are untouched. A rejected server now says why — `MCP server 'x' was rejected: url must not contain a query string.` — in an API-call failure, in **Dext: Check All APIs** output, and in **Dext: Verify MCP Server**, which can now select any configured server (HTTP, stdio, or one a rejected manifest dropped). Display paths mask every query value (`?key=***`), so a credential never reaches a log, diagnostic, picker, or resource list.

- Keep a followed conversation at its newest output. Dragging the conversation's scrollbar to the bottom used to stop short whenever output arrived in the same frame the drag was measured in, because the drag acted on a height from an earlier frame and the correction that would have fixed it was cancelled by the drag's own scroll event. Once the view sat more than 24px from the end, every later batch measured "not at the end" and stopped following for the rest of the turn, so the thumb stayed where the content used to end until **Jump to latest** was clicked - and the next batch left it there again. Following is now the reader's intent rather than a per-batch measurement: a scroll event the app did not start (a clamp after a disclosure shrank, or a correction one frame behind its content) never cancels a pending correction, a drag released against the track's end snaps to the height of the frame it was released in, wheeling up or a drag released above the end hands control back, and returning to the end - by wheel, keyboard, or the jump control - resumes following. The conversation also disables browser scroll anchoring (`overflow-anchor: none`), since re-rendering streamed Markdown removes the node the browser had anchored to, and the jump control now focuses the conversation so PageUp/End move it.

- Never park a turn on a question nothing can render. A harness question is answered through the Dext card, so the runner now requires both halves — the answer callback and the event sink that publishes `waiting` / `answered` / `dismissed` — and reports "no Dext surface" instead of waiting for an answer nobody can give. Dext's private question channel also answers any frame it cannot render with `unavailable` rather than staying silent, so a protocol mismatch reaches the model as the shipped fail-closed error instead of hanging `ask_user_question` until the turn is cancelled.

- Reassign a variable anywhere, not only inside `while`. `slug = slug.replace(" ", "-")` followed by `slug = slug.replace("/", "-")` used to fail with `dext/reassign` unless it was wrapped in a `while True:` block, because only a loop raised the compiler's loop-reassignment depth. The restriction is gone: sequential code, `if`/`for`, and `try` bodies all reassign an existing name, and a name written twice is materialized as a runtime `=` step instead of being inlined. That last part also fixes a latent bug the loop-only rule hid: in `count = 0` / `while count < 3:` / `count = count + 1`, every read of `count` folded to the first constant, so the condition stayed `0 < 3` and the loop never ended. A name still keeps the type it was first bound to — `value = 1` followed by `value = "two"` reports `dext/reassign` — because a variable that changed type would make each later read and API argument check depend on which path ran. `+=` is still rejected, and its message now also points at the reassignment to write instead of only at `"\n".join(lines)`.

- Show the Dext question card for a DeepSeek Harness `ask_user_question`, and for ACP elicitation. The Harness runner asked Dext's UI for the answer but never published the `waiting` / `answered` / `dismissed` input event the Codex runner uses to render and close that card, so the tool call parked the turn with nothing on screen to answer - even though the private question channel and the preset overlay were wired correctly. Secret answers are still never echoed into the transcript.

- Report `.dx` problems where they are written. The loader no longer joins its errors into one positionless string: each diagnostic keeps its file, line, column, stable code (`dext/compile`, `dext/must-return`, `dext/unknown-api`, `dext/reassign`, `dext/missing-rule`, `dext/signature`, `dext/syntax`, `dext/cycle`, `dext/duplicate-api`, `dext/mcp`, …), and API id, every independent error in a file is reported instead of just the first, and one failing file no longer hides the rest. `.dx` files now write to the **Problems** panel as you type (debounced), including from an unsaved buffer; **Dext: Check All APIs** checks the whole project into the same collection and the **Dext API Check** output channel with an `N error / M warning` summary; **Reload APIs** reports the same details; and entry is cleared when its file is deleted, even while its editor tab is still open. Each diagnostic also names the function it is in. A dependency cycle is named on the APIs that actually form it instead of being repeated on every loaded API.

- Name the missing MCP tool instead of its root. A call to an unregistered `mcp.<server>.<tool>(...)` compiled the `mcp` root as a variable and reported `Unknown variable 'mcp'.`, which hid which tool was missing; the API path now resolves and reports `Unknown Dext API 'mcp.<server>.<tool>'`.

- Report why a custom API call failed. A registered API whose function body did not compile used to fail with a bare `Custom API 'dev.fix' is not available.`; it now names the file, the function, the reason, and the line, says the method is registered but its body failed to compile, and distinguishes a declared MCP tool whose server is not connected from a plain unknown name and from an untrusted workspace that disabled custom APIs.

- Fix the `.dx` examples in the README and the workflow reference: built-in APIs are always in scope, so `from common import ask` never resolved and the copied example failed to load. The `Imported API 'common.ask' is not defined.` error now names the direct call to write instead.

- Fix `def main() -> McpRawResult` being rejected with "must return mcpRaw result": the return-kind check compared a camelCase kind (`mcpRaw`) against a lowercased PascalCase type name (`mcprawresult`). The unresolved-name squiggle in expression position also now covers the callee instead of its argument list, and a failed return expression no longer repeats itself as "A custom API function must return a value."

- Fix Harness session restore, which failed every resumed conversation with the protocol's generic `Internal error`: Dext's preset plugin forwarded only the agent-context argument to the deepseek Harness agent factory's `setup`, dropping the agent the resume path composes its model selection from.

- Report the cause behind a generic Harness `Internal error` — the ACP error's `data` payload plus the process's stderr tail — instead of the placeholder, and continue in a new session whose prompt carries this conversation's own context when the Harness refuses to restore a stored one, saying so in Process.

- **Breaking:** the Harness **Agent preset** menu now lists exactly the installed Harness catalog, with no Dext-only **ACP default** entry: every Harness conversation mounts a preset, and an unset or previously empty selection runs Standard instead of the profile's own agent composition.

- Add text and value expressions to the workflow language: string concatenation with `+`, Python f-strings with conversions (`!r`), format specs (`.2f`, `,`, `>8`), nested specs and `{value=}`, `%` formatting, `str.format`, indexing and slicing (`text[1:4]`, `text[::-1]`), membership tests, ordering comparisons, `and`/`or`/`not`, Python string methods, and the pure helpers `len`, `str`, `repr`, `int`, `float`, `bool`, `abs`, `round`, `min`, `max`, `sorted`, `sum`, `range`, `list`, `reversed`, `any`, and `all`. A value the compiler can determine is folded while compiling, so `"a" + "b"` behaves exactly like `"ab"` in every check; everything else stays a pure runtime expression with no API round trip. `elif` chains now keep every condition instead of quietly running the first body.

- Accept Python tuple syntax as list syntax: `("a", 1)`, `(value,)`, `()` and the bare `1, 2` all compile to a list, so `startswith((".md", ".txt"))`, `"%s %d" % ("total", 3)` and `"%s" % (items,)` can be written exactly as in Python. There is still one sequence type: a tuple is not fixed-length and `(1, 2) == [1, 2]` is true, and unpacking stays unsupported (`a, b = pair` reports that Dext assigns one variable at a time).

- **Breaking:** reject assignment shapes that used to compile by dropping part of the statement: `a, b = value` lost the extra name, and `a = b = 1` bound only `a`. Each now reports the shape it does not support. `x = 1, 2` used to silently bind only `1`; it now compiles as the tuple Python sees, which is a list.

- Parse Codex `config.toml` with `smol-toml` instead of line regexes, so comments, sections, and string escapes no longer break CLI path and model defaults.

- Add `agent(patch=false)` for text-only previews that report conclusions without producing a patch; route Agent result parsing through one tolerant boundary with one bounded ax-driven repair attempt, and return the harness final message instead of throwing "returned invalid JSON" so failures stay diagnosable.

- Separate long-term project knowledge from per-run conversation Review. Project knowledge lives in `.dext/project.json`, `.dext/objects/*.json`, and `.dext/architecture.json`, and every object now carries independent source, confirmation, validity, and ownership dimensions; the legacy `status` field is migrated on read. Review is keyed by session, turn, and run, and records the project version, plan version, and Build run it was produced against, so feedback can never land on another run or an older attempt.

- Unify Project, API, Global Resources, and History editor tabs behind stable keys, versioned state, and a restore path that keeps one panel per key. A page persists its own state, so reopening a window restores the same page and target, and a panel restored without usable state is rendered or dropped instead of being left blank. The Project tab exposes only Overview, Knowledge, and Diagrams.

- **Breaking:** remove the source scanner (TypeScript/JavaScript, Python, Rust and `Cargo.toml`) and the per-format diagram adapters (draw.io, Mermaid, Structurizr). Project knowledge now comes from an explicit, user-triggered AI initialization over a bounded, redacted evidence package, and one pinned Archify runtime renders all five diagram kinds from Project's own semantic IR. HTML and SVG are the only export formats.

- Add a **Diagrams** page that embeds the rendered Archify viewer in a sandboxed frame: select a saved diagram, generate or update one from a requirement, refresh, export HTML/SVG and go fullscreen, with validation, version and evidence coverage in a collapsed section. A failed render keeps the same diagram's last successful result visible and labels which version is on screen.

- Add declared architecture rules: `.dext/architecture.json` may carry `diagramId` and `rules` (`deny`, `allow`, `no_cycles`) over stable Project node ids, and the Diagrams page lists those rules with the violations the saved diagram currently has. Rules that cannot be evaluated against a diagram are reported instead of being applied to a guess.

- Persist the last successful render of each diagram in `.dext/diagram-history.json`, newest first and bounded in size, so a later failed render can still show the previous result after a window reload instead of only within one session.

- Add engineering and experience review presets that change what a review emphasizes.

- Add `docs/project-development.md` and `docs/project-development.zh-CN.md` describing the project-knowledge and conversation-Review model.

- Show every development turn's Review inside its conversation: the files the run changed, the script facts and coverage it recorded, knowledge drafts, and accept or request-changes actions. A review is bound to its session, turn, and run, an Ask turn or a turn with no change produces no card, and writing a plan produces no implementation review.

- Accumulate Plan builds into one review bound to the plan content version and Build run. Proven task associations are grouped by task ID, while shared and unattributed changes are listed separately instead of being inferred from the agent's task checkmarks, and the final acceptance waits for the user instead of letting the Agent continue.

- Add a knowledge adoption bridge: each pending draft has its own **Adopt** action that writes one long-term object and opens it in Project. Accepting the code review stays a separate action and writes no project knowledge.

- Move the API directory and Global Resources out of sidebar dialogs into editor tabs. Search, namespace grouping, detail, reference insertion, source jumps, categories, and refresh are preserved, and reopening the same target reveals the existing page. `dext.editResource` opens the existing resource edit flow for a kind and scope.

- File MCP tools under **MCP** on the Resources page and nest each category the way the API page does. An MCP tool is registered as the `mcp.<server>.<tool>` API, so the page listed every tool under **API** even though it is MCP content; the category now follows the `mcp.` id instead of the resource's storage kind, while the entry still opens and inserts as the callable API it is. Each category was also one flat list, so `dev.feat` and `dev.fix` read as unrelated rows: a category now nests its dotted namespaces (`dev` holding `feat`, `fix` and `plan`) and an MCP category nests its own server (`teamibition-user` holding its tools) with per-node counts and remembered collapse state, matching the API directory's tree.

- Read the plan's Review preset default synchronously from the cached project definition, so a send freezes the effective preset without waiting on file I/O.

- Let `ui.form` declare several submit buttons through `actions`, each with its own `id`, optional `primary` highlight and `requires` list of fields it needs answered; the pressed button comes back as `action`. A decision that used to need a radio field plus a conditional text box is now one button per outcome, and the form no longer reports unmet requirements before the user has pressed anything.
