# 项目文档更新

写入阶段：按审计结论更新 `docs/`，让文档与代码一致。只产出文档改动。

## 写入范围

- 只修改 `docs/` 下的 Markdown 文件，新页面也建在这里。
- 仅在新增或删除页面时改动 `README.md` 与 `README.zh-CN.md` 指南表格中对应的行，不改 README 的其他内容。
- 不修改 `src/`、`test/`、`scripts/`、`package.json`，也不改 `.dext/` 下的任何文件。
- 不动与本次审计无关的段落、标题层级与链接顺序。

## 处理顺序

1. 先修 stale 页面中与代码事实冲突的句子与示例：命令、配置键、默认值、限制、界面文案。
2. 再补 partial 页面缺失的章节，插到最相关的相邻章节之后，不重排现有章节。
3. 最后处理新增与删除：新页面按写作规范建中英两版；删除页面时同步移除指向它的链接与 README 表格行。
4. 中英成对推进：一侧改完立即在同一次改动中完成另一侧，使两版章节、顺序、示例数量一致。

## 证据要求

- 写入的每条事实都来自代码或 `package.json`；无法确认的内容不写，不用“通常”“一般”填空。
- 命令直接取自 `package.json` 脚本，参数取自 CLI 定义，不手写变体。
- 示例中的路径、键名、类型名与代码逐字一致。

## 最小差异

- 优先改句子而非重写段落，优先改示例而非重排章节。
- 删除内容必须有依据：能力已移除或描述与代码冲突。
- 不引入新的写作风格，沿用页面现有的人称、时态、列表标记与代码块风格。

## 结束时

在结果摘要中列出：新增页面、更新页面、删除页面、未处理项及原因。不要在文档里写变更记录。
