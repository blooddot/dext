# 项目文档写作规范

适用于 `docs/` 下的页面。它约束怎么写，不决定本次改哪些页面。

## 读者与事实

- 每个页面服务一个问题：怎么用、怎么配、为什么这样设计。首段两句话内说清本页解决什么，不写“本文介绍……”。
- 只写当前代码的事实。不写路线图、猜测、TODO、版本承诺。
- 每条事实都应能在代码或 `package.json` 中找到依据；找不到依据的内容不写。

## 页面骨架

- 第 1 行是 `# 标题`。英文用句首大写，中文用简洁名词短语，不加编号。
- 第 3 行是语言切换行：英文页 `English | [简体中文](<name>.zh-CN.md)`，中文页 `[English](<name>.md) | 简体中文`。
- 切换行之后是返回链接：英文页 `[Back to README](../README.md)`，中文页 `[返回 README](../README.zh-CN.md)`。
- 返回链接之后依次是：一段摘要、用 `·` 分隔的页内锚点行、各 `##` 章节。
- 层级只用 `##` 与 `###`；`####` 仅在确需再分步骤时使用。
- 不加 `---` 分隔线、日期、作者、修订记录，也不写“目录”两字。

## 语言与术语

- 中英两版一一对应：同章节、同顺序、同示例、同数量。改一侧必须同批改另一侧。
- 命令、路径、文件名、配置键、API 名称、类型名、代码标识符、界面按钮文案保留原文，不翻译、不改写大小写。
- 界面元素用 `**Bold**` 标注，例如 **Workspace write**。
- 中文页用简体中文陈述句，避免“我们”，避免营销语气；英文页用现在时的陈述句或祈使句。

## 示例与链接

- 命令必须能在本仓库直接运行，优先复用 `package.json` 中已有的脚本，不编造脚本或参数变体。
- 代码块标注语言（`ts`、`bash`、`json`、`md`），只保留说明问题所需的行；示例输出必须与真实输出一致。
- 路径一律用仓库相对路径；链接用相对链接（`mcp.md#tools`、`../README.md`），不用绝对路径或本机路径。
- 新增页面时在 `README.md` 与 `README.zh-CN.md` 的指南表格各加一行；删除页面时同时删掉这两行。
- 一个概念只在一个页面详细说明，其他页面链接过去；重命名章节时同步修复所有指向它的锚点链接。
