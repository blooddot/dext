# 按宿主清单审查工作区

Dext 已在输入里给出本轮文件清单、既有问题 ID 和输出格式。以宿主清单计覆盖，每个路径都要审查或说明跳过原因。候选调用点只供查证具体行为，沿用和待另行审查的文件留在各自的范围内。

## 查证

- 只执行只读检查。保持工作区、暂存区和提交历史原样。
- 已跟踪文件用 `git --no-pager diff --no-ext-diff --no-textconv --no-color HEAD -- <path>` 查看改动，未跟踪文件直接读取。仓库尚无提交时，通过暂存差异和工作区现状核对。工作区干净但有待复核文件时，读取文件现状。若同一路径同时列出暂存删除 `D` 和未跟踪 `??`，分别检查 `git diff --cached -- <path>` 和重建后的工作区文件，两部分都覆盖才算审完该路径。
- 可用 `ocr delegate rule --format json <paths...>` 查宿主清单内文件的项目审查规则。OCR 缺失或无法返回规则时，按仓库可读的规则和已有证据继续。审查范围始终由宿主清单决定。
- 初次审查只报告有证据的问题，给出触发条件和实际影响。修复复核逐条对照 ID 和提供的修复差异，只有能关联到差异的直接回归进入新发现。其他观察写入「另行审查」。

## 报告

- 按输入指定的 Markdown 小节和逐条格式输出。在「既有问题复核」逐条给出验证证据，证据不足时保留 `open`。
- 在「本轮未审文件」列出宿主清单内未审的路径及原因，全部完成时写 `（无）`。实际运行的检查写明命令和结果。
