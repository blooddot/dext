# 发布说明（release/notes）

把 `since...HEAD` 的用户可见变化整理成发布页面可用的中英双语发布说明。只读：不写 CHANGELOG，不改代码，不打包。

## 输入

- `git diff --stat` 与 `git diff` 全文：本次发布相对起点的全部改动。范围过大时调用方改送 `git log --oneline` 的 commit 列表。
- `CHANGELOG.md` 的本版段落原文；可能缺失。
- 版本号、项目名与日期由调用方给出，你只填字段值；标题、节名、节序与列表符号由 `.dext/templates/release/notes.md` 渲染，不要自己写。

## 与 CHANGELOG 的关系

- CHANGELOG 本版段落是主要来源：它已经过分类与去重，发布说明在它基础上改写，不必重新逐条读 diff。
- CHANGELOG 缺失时只依据 diff 整理。
- 两者冲突时以 diff 为准。
- 发布说明比 CHANGELOG 短：CHANGELOG 保留全部用户可见条目，发布说明只留升级者最需要知道的部分。

## 分类

每条候选内容只归一类，按下面的顺序判断：

1. **highlights**：本版最值得知道的 1-3 条结论（最重要的功能、最大的破坏性改动）。
2. **breaking**：会打断既有用法的移除或语义变化，每行写 `**变化** — 可执行的迁移动作`。
3. **features**：净新增且用户可感知的能力。
4. **fixes**：修好的用户可感知缺陷。
5. **notes**：其他用户可感知的影响，例如性能、兼容性、已知问题。

过程条目（本版加了又删、改了又改回去）一律不写；内部重构、变量改名、测试改动与依赖小版本升级也不写。

## 写法

- 英文与中文各写一份：`en` 在前、`zh` 在后，条目一一对应（条数、顺序、分类相同）。
- 标识符、配置键、路径、命令与报错在两种语言里都保持原文；CHANGELOG 现有条目是英文，`zh` 里译成中文，`en` 里可以沿用原文。
- 面向升级者：说清楚什么变了、对他有什么影响、要不要动手。
- 每条一行，动宾结构，必要时用反引号给出标识符、配置键或路径。
- 条目不要带 `- ` 前缀，也不要带版本号、日期或 `##` 标题；调用方负责渲染列表。
- `migration` 必须是可执行的替换动作：改哪个文件或配置键、改成什么、改完是什么样。
- 只写 diff 或 CHANGELOG 能证明的内容；没有证据就不写，也不要为了凑满小节编造。
- 同一变化只出现一次；每节最多 12 条。

## 字段

提示里的字段清单就是模板 frontmatter 的声明：`<节>_en` 与 `<节>_zh` 成对出现，两语言条数、顺序、分类一一对应。字段说明已写在各字段描述里；空内容的节不要勉强编写，留空即可（模板会连带它的标题一起剪掉）。
